# 출제 지침 (전 카테고리 공통)

## 1. 데이터 형식
- 파일: `data/{카테고리코드}-{회차}.json`. 등록은 `manifest.js`의 `tests`에 `"{코드}-{회차}": { title }`.
- 공통 필드: `category`, `round`, `title`, `subtitle`, `instruction`, `total`(= questions 길이), `study`(개념 정리 탭, 선택), `questions`.
- 문항 `type` 네 가지. `num`은 1부터 순서대로(회차 안에서).
  - `process` — 음운 변동 과정 완성. `start`, `steps:[{accept:[규칙…], form}]`. 파일에 `ruleOptions`(규칙 드롭다운 목록)가 있어야 하고 `accept`의 값은 전부 그 목록 안에 있어야 한다. 선택 `hint`(풀기 전에 문항 위에 연보라 상자로 보임)·`explanation`(채점 뒤 해설).
  - 모든 type에 `hint`를 둘 수 있다(문항 머리 아래 '힌트' 상자). **같은 규칙이 한 문항에 두 번 이상 나오는 process 문항은 `hint`와 `explanation`을 반드시 쓴다**(2026-09-13 사용자 요청 — 왜 두 번인지, 어느 자리가 먼저인지).
  - `short` — 단답. `stem`, `answer`, 선택 `answers`(추가 인정 정답), `explanation`.
  - `ox` — `stem`, `answer:'O'|'X'`, `explanation`.
  - `choice` — `stem`, `options`(2개 이상, 중복 없음), `answer`(1부터 번호), `explanation`.
- 회차 문항 수: 음운 21~22, 맞춤법 15(1회차만 10). 새 카테고리는 사용자와 정한다.
  - 형태소: 레벨1·레벨2 각 10회 × 15문항(2026-09-13 사용자 지정). `process`를 **형태소 나누기**로 재사용한다 — 파일의 `processUI`가 드롭다운·입력칸·해설 문구를 바꾼다(기본값은 음운 변동 문구). `ruleOptions` = 실질·자립/실질·의존/형식·의존.
- 형식 검사: `node tools/data-check.js` (전 파일). 통과 전에는 커밋하지 않는다.

## 2. 채점 제약 (문항을 만들 때 반드시 지킬 것)
- `normalize`가 **공백을 지운다** → 띄어쓰기 자체를 단답으로 묻지 않는다. 띄어쓰기 문항은 `choice`로.
- `process`는 **규칙과 형태를 따로 채점**한다. 규칙만 맞고 형태가 틀려도 규칙 점수는 인정된다. 그래서 규칙과 형태가 어긋난 조합('반모음 첨가'+'살펴')도 정답이 될 수 있다 — 구조 한계이므로 문항 설계로 피할 것(한 단계에 정답 조합이 하나만 나오게).
- `process`의 `form`은 **대괄호 없는 한글**, 장음 표시(:)를 쓰지 않는다. 두 가지 형태를 다 인정할 땐 `'기어서/기여서'`처럼 빗금으로.
- `accept`에 규칙을 둘 이상 넣으면 어느 것을 골라도 정답(예: 사잇소리 현상/된소리되기가 갈리는 경우).
- `ox`·`choice`·`short`는 `explanation`을 반드시 쓴다. 근거 규칙(또는 조항) 이름을 명시한다.

## 3. 문항 작성 원칙
1. **근거는 knowledge 문서**. 문서에 없는 규칙·예외를 문항에 쓰지 않는다. 필요하면 사용자에게 자료를 요청한다.
2. **용어는 학교 문법(교과서) 용어**. 음운 문서의 용어표를 따른다(예: '음절의 끝소리 규칙', '된소리되기', '거센소리되기', '자음군 단순화', 'ㄴ 첨가'). 학술 용어(평파열음화·경음화·격음화)는 해설 보조로만.
3. **정답이 하나로 떨어져야 한다**. 학설이 갈리는 지점(예: ㅎ+ㅅ→[ㅆ]이 축약인지 교체+탈락인지, 겹받침+된소리의 적용 순서)은 **그 갈림 자체를 묻지 않는다**. 교재도 같은 태도다(4-2 해설 484·485).
4. **오답 선지는 이유가 있어야 한다**. 각 오답이 왜 틀렸는지 한 문장으로 설명할 수 있어야 하고, 그 이유는 `pho-03-기출유형.md`의 오답 패턴(연음을 변동으로 오인, 형식/실질 형태소 혼동, 조음 위치/방법 혼동 등)에서 고른다.
5. **같은 단어를 여러 회차에 되풀이하지 않는다**(`pho-audit.js`가 `start` 중복을 알려 준다). 같은 규칙을 다른 단어로 묻는다.
6. 한 회차 안에서 규칙이 골고루 나오게 하고, 2단계 이상 문항을 3분의 1 안팎 섞는다(음운 기준).
7. 형태소 경계가 보이는 예(용언 활용형·조사 결합형·합성어)를 우선한다 — 규칙 적용 조건(형식/실질 형태소)을 학생이 판단하게 하려는 것.
8. 사용자가 확정한 표기·디자인 지침(CLAUDE.md)은 문항 텍스트에도 적용된다: 이모지 금지, 취소선 금지.

## 4. 검토 절차 (만든 뒤)
1. `node tools/data-check.js` — 형식.
2. `node tools/pho-audit.js` — 음운 process 문항의 단계별 정합성(규칙과 형태 변화가 맞는지, 최종 발음의 받침이 7개 대표음인지, 미결 순서 유형이 몇 건인지, 단어 중복).
3. 사람 검수(사용자). 검수 결과 새로 정해진 규칙은 해당 카테고리 문서의 '결정 사항'에, 못 정한 것은 '미결 사항'에 적는다.
4. 배정·응시는 E2E(`tools/e2e-test.js`)로 회귀 확인.

## 5. 하지 말 것
- 자료 없이 문항 내용을 지어내는 것(어휘·문법 저장소 공통 지침).
- 미결 사항을 임의로 정해 데이터를 고치는 것 — 사용자 결정 뒤에.
- 시판 교재의 기출 문항 본문을 그대로 옮기는 것.
